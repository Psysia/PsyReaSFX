# PsyReaSFX 0.9 神经音频相似度架构

更新日期：2026-09-15
状态：第三阶段进行中；Lua 可选接入、进度、取消、混合重排与故障回退已实现，通用媒体解码尚未完成，未进入公开 Beta

## 1. 目标与边界

Beta 4.5 已交付基于 RWF4 的 15 维手工声学特征、精确分桶剪枝和固定 Top-200
结果堆。该实现继续作为无需额外组件的基础模式，并承担神经检索后的声学重排与
故障回退，不删除、不替换其缓存格式。

下一阶段增加可选的 AudioSet embedding，用于表达事件、材质、场景和复杂纹理；
HNSW 只负责从大库中快速召回候选，最终排序仍结合现有时长、起音、瞬态、包络与
频谱统计。首版不做文本搜声音、不联网推理、不上传音频，也不根据文件名、UCS 或
用户标签修正 embedding 分数。

## 2. 模型配置

首个实现基于 EfficientAT 的公开 AudioSet 权重和 EfficientAT_HEAR 的多层特征方案。
模型代码与上游仓库内实际 `LICENSE` 文件采用 MIT 许可；
EfficientAT_HEAR 的 `setup.py` 许可元数据错误标成 Apache-2.0，发布记录以固定提交中
两仓库一致的 MIT `LICENSE` 文件为准。模型权重来源、SHA-256、上游提交和许可文件
均已写入模型清单与第三方声明。

### 默认档：`mn04_as`

- 模型参数约 0.983M，AudioSet mAP 43.2；
- 拼接 b5、b11、b13、b15 的池化特征和 128 维 mel 均值；
- 每个素材输出 320 维 scene embedding；
- 作为默认档，优先控制 CPU 推理时间、安装体积和几十万条索引的内存压力。

### 可选质量档：`mn10_as`

- 模型参数约 4.88M，AudioSet mAP 47.1；
- 使用同一多层特征方案，每个素材输出 600 维 scene embedding；
- 仅在真实素材盲测证明质量收益足以覆盖推理和索引成本后进入正式发布。

模型标识必须包含模型名、权重 SHA-256、导出器版本、预处理版本、输出节点和维度。
任一字段变化都生成新索引，不允许把旧向量静默解释为新模型结果。

## 3. 冻结的音频预处理

- 解码后转为单声道 float PCM，固定重采样到 32,000 Hz；
- 预加重系数 `0.97`；
- STFT：`n_fft = 1024`、非周期 Hann 窗 `win_length = 800`、`hop = 320`；
- 128 个 mel 频带，使用 EfficientAT 相同的频率边界、对数和 `(x + 4.5) / 5`
  归一化；
- 10 秒以内直接生成 scene embedding；长文件按 10 秒窗口、2.5 秒 hop 分段，
  对所有窗口向量求平均；
- 最终向量做 L2 归一化，ANN 距离使用 cosine distance。

ONNX 图同时冻结预处理，并通过官方 PyTorch、冻结 PyTorch、ONNX Runtime 与 .NET
sidecar 的跨运行时金样测试。当前 `mn04_as_scene_320_v1` 图输出每个窗口的原始 320
维向量；sidecar 对长文件按 10 秒窗口、2.5 秒 hop 求平均后统一做 L2 归一化，避免
错误地先归一化每个窗口再平均。不能只导出分类网络后在宿主侧近似复刻 mel 计算。

## 4. 运行与发布架构

REAPER Lua 不直接加载 ONNX Runtime，也不要求用户安装 Python。神经检索由独立的
Windows x64 sidecar 执行，Lua 继续拥有界面、任务协调、当前素材和结果展示。

sidecar 的第一阶段职责：

1. 校验自身版本、模型清单和文件哈希；
2. 解码音频、运行 embedding 推理并原子写入缓存；
3. 增量建立、加载和更新 HNSW；
4. 接收参考素材与候选范围，返回稳定签名和 ANN 分数；
5. 响应取消文件，在当前素材完成后停止，不留下半条向量或半成品索引。

当前实现已完成模型清单逐文件 SHA-256 校验、`capabilities`、PCM16 32 kHz WAV
的 `embed`、10 秒窗口/2.5 秒 hop、三条金样自检，以及 `run-job` 文件协议下的增量
FP16 embedding 缓存、取消、离线复用、候选签名过滤与精确 cosine Top-K 查询。
当前还实现了不增加第三方运行时依赖的确定性 HNSW 图、原子索引替换、缓存 SHA-256
绑定、取消保护和损坏/过期索引的精确查询回退。Lua 已通过原子文件任务接入能力
探测、进度、取消、HNSW/精确查询、15 维声学重排与故障回退；协议 v1 只在整个搜索
范围均为 32 kHz PCM16 WAV 时启用，通用媒体解码/重采样仍属于下一阶段。

sidecar 是可选组件。未安装、模型缺失、版本不匹配、进程崩溃或索引损坏时，
“查找相似声音”必须自动回退到 Beta 4.5 的 15 维精确检索，并给出一次非阻塞状态
提示；基础浏览、试听、扫描和 Transfer 不得依赖 sidecar。

首版不把 Desktop 进程作为 Lua 的隐式常驻服务。Lua 和 Desktop 后续可以复用同一
sidecar、模型与索引格式，但二者必须通过显式版本协议访问，不能直接双写文件。

## 5. 文件协议与数据安全

所有请求、状态和结果先写临时文件，完成后同目录原子替换。协议使用带 magic 和
版本号的 UTF-8 文件；路径字段必须进行无损编码，不使用未经转义的命令行拼接。

建议的数据目录：

```text
<PsyReaSFX data>/neural_similarity/
  models/manifest-v1.tsv
  embeddings-<profile>-v1.bin
  embeddings-<profile>-v1.manifest
  hnsw-<profile>-v1.bin
  jobs/<request-id>.request
  jobs/<request-id>.status
  jobs/<request-id>.result
  jobs/<request-id>.cancel
```

- 索引使用与现有相似缓存兼容的 16 字符素材签名作为外部键；sidecar 额外校验文件
  大小和最后写入时间，模型版本变化时整体失效；
- HNSW 内部节点只保存数字 ID，持久化映射只保存签名，不写完整素材路径；
- embedding 和 HNSW 都是可重建缓存，不进入用户元数据、收藏、播放列表或项目箱；
- 损坏、截断、维度错误、模型哈希不符或重复签名必须拒绝载入并安全重建；
- 清理缓存只删除神经相似度目录，不触碰 RWF、素材数据库或源音频。

当前缓存版本使用 `PSYNEMB1` magic、格式版本、profile、模型 SHA-256、维度和记录数
组成头部。每条固定记录只含 16 字符签名、文件大小、UTC 修改时间 ticks 与 320 个
little-endian FP16 值。构建清单使用 UTF-8 TSV，路径列是 JSON string，避免制表符和
非 ASCII 路径破坏字段边界。旧记录只有在大小和修改时间完全匹配时才复用，因此
离线盘不阻止安全复用；需要重算但源文件不可用时只记录该素材失败。

HNSW 索引使用 `PSYHNSW1` magic，并保存格式版本、profile、模型哈希、完整 embedding
缓存哈希、`M`、`efConstruction`、入口节点、最高层和逐层邻接表。默认参数为
`M = 16`、`efConstruction = 128`、`efSearch = 800`。节点顺序和层级由素材签名确定，
同一缓存和参数重复构建产生相同文件。缓存发生任何变化时当前版本会重建整个图，
不会尝试把旧图静默绑定到新向量。

## 6. 召回与重排

首轮查询流程固定为：

1. 为参考素材获取并缓存 embedding；
2. 无范围限制时由 HNSW 按 cosine similarity 召回最多 1,000 个候选；候选签名过滤
   继续使用精确 cosine，避免小集合在 ANN 阶段漏项；
3. 排除参考素材，并按当前结果/全部音效库范围过滤；
4. 对候选读取现有 15 维特征，计算时长、包络、起音、瞬态、动态和频谱差异；
5. 输出固定 Top 200，并继续使用当前列表的相似度列和解释标签。

最终混合权重在盲测前不冻结。实现必须把 embedding 分数与声学重排分数分别保留在
内部结果中，以便回放测试和调参；任何调参都不得要求重新计算 embedding。

当前结果范围不能依赖“先查全库再丢弃大部分候选”的固定 1,000 召回，否则小集合
可能漏掉正确结果。sidecar 必须支持候选签名过滤，或逐步扩大 `efSearch`/召回数量，
直到满足范围内的 Top 200 或已穷尽索引。

## 7. 容量预算

以未压缩向量估算：

| 配置 | 维度 | FP16 / 50,000 | FP16 / 500,000 |
|---|---:|---:|---:|
| `mn04_as` | 320 | 约 30.5 MiB | 约 305 MiB |
| `mn10_as` | 600 | 约 57.2 MiB | 约 572 MiB |

以上不包含 HNSW 邻接表、节点元数据和构建峰值。第一阶段发布门槛仍以 50,000 个
真实音频为主；500,000 条要求元数据目录保持可用，并验证分片/按需索引不会造成
无界内存增长。未经召回率测试，不启用 int8 或低维投影作为默认格式。

## 8. 验收门槛

### 正确性

- 官方 PyTorch 与发布用 ONNX 对固定金样的 cosine 相似度误差不超过冻结阈值；
- 同一模型、CPU 和重复运行生成稳定向量；
- 增量追加、文件变化、离线盘、取消、崩溃和重启不会返回错误素材签名；
- ANN 对固定测试集的 Recall@200 达到冻结门槛，并与穷举 cosine 基线对比；
- sidecar 不可用时，Beta 4.5 的结果和回归测试保持不变。

### 质量

- 建立脱敏人工标注集，至少覆盖武器、脚步、机械、载具、环境、动物、界面、冲击、
  魔法和材质变化；
- 使用 triplet/Top-K 盲测比较纯 15 维、纯 embedding、embedding + 重排；
- 分别记录相同事件不同录音、相同材质不同事件、长氛围、短瞬态、多声道和压缩格式；
- 只有组合方案在人工偏好和 Recall@K 上稳定优于 Beta 4.5，才替换默认排序。

### 性能与发布

- 记录 `mn04_as` CPU 单文件推理、50,000 文件首次建库、取消延迟、增量更新、冷启动
  索引加载和查询 P50/P95；
- REAPER UI 在推理和建索引期间保持可交互，试听优先级高于后台分析；
- helper、ONNX Runtime、模型权重和 HNSW 依赖均有固定版本、SHA-256、许可证和
  可复现构建记录；
- ReaPack 默认安装仍可不包含神经组件，用户必须明确选择下载体积更大的可选包。
