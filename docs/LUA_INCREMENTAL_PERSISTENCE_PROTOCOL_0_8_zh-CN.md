# Lua 素材增量持久化协议

记录日期：2026-09-02

## 目标

在 500,000 条素材目录中，收藏、工作流、试听次数、元数据和封面等少量变化不再
触发完整 `index_v3.tsv` 重写，同时保持原子快照、备份恢复和未来版本只读保护。

## 安全约束

1. 基础快照拥有单调递增的 `generation`；
2. 增量日志必须声明它所属的基础快照代次；
3. 代次不一致的日志绝不重放，防止压缩后的旧日志覆盖新快照；
4. 每条记录带校验码，整个文件必须以完整换行结束；
5. 解码器先验证完整日志，再向目录状态应用记录，禁止部分重放；
6. 日志压缩先原子提交新快照，再清除旧代次日志；中断后旧日志因代次不匹配自动失效；
7. 结构性扫描、来源删除和重定位在完成脏记录接入前继续走完整快照，不冒险推断删除范围。

## 已完成

- 独立 `36_asset_journal.lua` 编解码模块；
- 代次、字段布局、操作类型、转义值和逐条 Adler-32 校验；
- 截断、内容损坏、错代次和错字段测试；
- 10,000 条确定性日志容量测试；
- 按素材身份合并的脏记录集合，同一素材只保留最后一次操作；
- 结构性变更可显式升级为完整快照，避免错误推断删除范围；
- 快照 schema 行内嵌单调递增代次，旧版读取器会安全忽略扩展字段；
- 启动时先完整校验日志，再重放更新与删除；错代次日志自动失效，损坏日志触发只读保护；
- 自动测试加入 CI，发布单文件由构建脚本自动包含该模块。

## 后续接入顺序

2. 日志达到条数或体积门槛后空闲压缩；
3. 增加“快照提交前/后中断”和重复重放故障注入；
4. 完成真实 REAPER 50 万目录保存与恢复测试。
