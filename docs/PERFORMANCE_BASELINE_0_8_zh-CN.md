# PsyReaSFX 0.8 性能基线

## 测试环境

- 日期：2026-09-01
- 系统：Windows 10.0.19045
- 逻辑处理器：16
- .NET：8.0.29
- 数据：`tools/generate_hardening_library.py` 生成的 5,000 个确定性短 WAV，包含重复候选、多声道文件和独立 Artwork 目录
- 流程：完整目录索引 → 新 SQLite 数据库完整保存 → 完整载入 → 内存搜索

测试数据位于系统临时目录，不属于发布包，也不包含用户素材。

## 首次基线

| 阶段 | 时间 |
|---|---:|
| 索引 | 5,241.4 ms |
| 完整保存 | 8,313.2 ms |
| 完整载入 | 28.4 ms |
| 内存搜索 | 0.46 ms |
| 托管内存增量 | 12.05 MiB |

结论：搜索和载入不是当前瓶颈；首次扫描的音频读取有优化空间，最明显的问题是完整保存。

## 第一项优化：批量读取旧路径身份

来源重定位检查原先针对每个素材单独执行一次 SQLite 查询。改为一次载入全部 `asset_id → path` 后在内存比较，仍在同一事务中迁移发生变化的引用。

| 阶段 | 优化后 | 相对首次基线 |
|---|---:|---:|
| 索引 | 4,658.6 ms | -11.1%（受文件缓存影响，仅供参考） |
| 完整保存 | 6,553.0 ms | -21.2% |
| 完整载入 | 26.9 ms | -5.3% |
| 内存搜索 | 0.54 ms | 绝对值仍低于 1 ms |
| 托管内存增量 | 12.05 MiB | 无变化 |

完整 Desktop 自检（包括路径迁移冲突回滚）在优化前后均通过。

## 后续基线

- 继续记录 50,000 和 200,000 条规模。
- 分离冷缓存与热缓存索引数据。
- 增加 UI 滚动、连续选择、试听期间后台任务和退出收敛时间。
- 完整保存仍超过交互可接受范围，后续采用脏记录/增量写入，不用进一步堆叠全量写入微优化。
