# PsyReaSFX 0.8 路径身份与来源重定位

## 身份模型

- `source_id` 是来源的永久身份；修改根目录时保持不变。
- `asset_id` 是素材的永久身份；绝对路径只表示当前位置。
- 每个素材额外保存来源内相对路径和最后成功访问时间。
- 每个来源保存显示路径、规范物理路径、可用时的卷标/卷序列号和最后在线时间。
- Lua 旧索引升级时按 `source_id + relative_path` 生成稳定身份；Desktop 已有 SQLite 目录升级到 schema 3 时先生成一次永久身份，之后不再因路径改变而重建。

## 重定位协议

1. 选择新来源后先生成计划，不修改目录：统计迁移、缺失、冲突和外部封面。
2. 新来源与已有来源发生重叠，或多个素材落到同一目标路径时拒绝提交并显示冲突。
3. 用户确认后才更新来源。Desktop 在同一个 SQLite 事务中迁移素材和全部路径引用；Lua 先创建完整恢复快照，再以原子文件替换提交。
4. 收藏、试听状态、播放列表、Region、响度和工程使用记录随永久身份迁移；已存在的目标引用采用集合并集或保留非空统计，不静默丢弃。
5. Desktop 事务失败会恢复旧目录、旧引用和旧 UI 快照；Lua 保存失败会反向迁移内存引用并重新写回旧路径。
6. 新目录中暂时不存在的文件保留在目录中并标记离线，不再被扫描静默删除。

## 自动回归

Desktop 自检会创建旧根目录和新根目录并执行真实迁移，验证：

- 根目录变化后 `asset_id` 不变；
- 描述、收藏、试听高亮、播放列表、Region、响度和工程使用记录全部跟随；
- 文件离线后身份仍保留；
- 相同 `asset_id` 的冲突提交会失败，且整个 SQLite 事务回滚；
- 真实 NTFS Junction、扩展路径前缀和尾斜杠会解析为同一规范来源；
- 同一卷序列号、同一卷内相对位置在盘符变化后仍识别为同一来源；
- Lua libraries schema 2 / database schema 3 的来源身份、素材身份及新增索引列
  能够由 Desktop 按列名只读导入；
- 未来 schema 仍被旧程序拒绝写入。

跨机器 UNC、映射盘和需要特权创建的符号链接组合保留在 RC 真实环境验收中；当前自动测试覆盖盘符大小写、尾斜杠、扩展路径前缀、真实 Junction、卷序列号盘符变化模型、根目录移动、部分缺失与冲突回滚。
