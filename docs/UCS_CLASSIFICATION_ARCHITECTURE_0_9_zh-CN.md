# PsyReaSFX 0.9 UCS 分类架构

## 目标与边界

0.9 的高级检索首先建立可审计、可回滚的 UCS 分类底座。当前阶段只自动接受能够被官方 UCS 8.2.1 数据唯一验证的结果，不使用模糊猜测直接改写用户资料。

## 数据来源

- 来源：Universal Category System 官方 8.2.1 完整翻译表。
- 内置目录：753 个唯一 CatID、82 个一级分类，以及英文和简体中文名称、解释与同义词。
- 生成前校验官方工作簿 SHA-256；生成脚本同时校验表头、记录数和 CatID 唯一性。
- 运行时只读取压缩后的离线 TSV，不依赖网络，也不把官方源工作簿打入发行包。

详细来源与校验值见 `assets/ucs/README.md`。

## 分类优先级

1. 文件名以合法 CatID 开头，并紧跟 `_`、`-`、空白或文件名结束：记为 `exact / filename`。
2. 文件名未命中时，精确读取音频元数据中的 CatID；若 CatID 无效，再校验 Category 与 SubCategory 组合：记为 `exact / metadata`。
3. 文件名与 Category/SubCategory 组合、子分类名或中英文同义词形成高置信唯一结果：记为 `auto / filename_keywords`。
4. 多个关键词结果接近，或证据不足以安全自动应用：不写入正式分类，保存前三个候选并记为 `pending / filename_keywords`。
5. 元数据存在但无法映射到官方目录：保留原值，记为 `pending / metadata`，等待后续候选确认界面处理。
6. 没有可用信息：记为 `unclassified`。
7. 用户手工修改 CatID、Category 或 SubCategory：记为 `manual`，后续自动索引不得覆盖。

文件名 CatID 匹配区分大小写并要求分隔符，避免把普通英文前缀误分类。元数据字段名使用确定性的叶节点精确匹配，避免 `CATEGORY` 错误命中 `SUBCATEGORY`。

关键词索引为每个 UCS 条目建立 Category/SubCategory 组合、子分类名、分类名与同义词倒排表。分类时只查询文件名实际出现的词元和最多四词短语，不逐条遍历全部 753 个条目。同一规范化词只计一次；命中长短语后不再重复累计其内部短词。分类名只是上下文弱证据，只有唯一子分类、分类与多个独立证据组合，或明确 Category/SubCategory 短语才能进入自动分类。最高候选与第二候选没有安全分差时始终进入待确认。

## 持久化字段

每条素材除 CatID、Category、SubCategory 外，还保存：

- `ucs_status`：`exact`、`pending`、`unclassified` 或 `manual`；
- `ucs_source`：`filename`、`metadata`、`manual` 或空；
- `ucs_version`：分类所用 UCS 数据版本；
- `ucs_classifier_version`：分类器规则版本；
- `ucs_confidence`：当前确定性分值。
- `ucs_candidates`：按分数排序的前三个 CatID 与分数；
- `ucs_evidence`：最高候选实际命中的去重词语。

这些字段随数据库表头扩展，不提升数据库主架构版本。0.8.5 可以读取同一数据库并忽略未知字段，便于 Beta 测试期间回退；旧版本再次保存时可能丢弃新增字段，但不会损坏核心素材记录。

## 性能与验证

- 运行时目录采用 CatID 哈希索引和 Category/SubCategory 组合哈希索引，单次精确分类为常数时间查找。
- CI 固定验证 753 条记录、82 个一级分类、中文字段、大小写与分隔符边界、元数据字段隔离。
- CI 每次执行 500,000 次 CatID 精确分类和 500,000 次多关键词分类，持续约束 50 万条素材库的基本规模目标。
- UCS 目录聚合缓存同样用 500,000 条合成素材执行 125 个分帧步骤，验证 Category、SubCategory 与 CatID 计数总量和分布。

## 现有库重分类事务

- 维护页采用“预览 → 确认应用”两阶段流程。预览阶段只统计结果和最多八条变化样例，不修改素材，也不保存每条素材的候选副本，因此不会额外持有 50 万份提案对象。
- 预览与应用都重新运行同一个确定性分类器，每帧最多处理 256 条并限制在 4 ms 时间预算内。应用前检查素材数组与数量以及分类器版本，拒绝把过期预览用于已经变化的目录。
- 应用阶段只写实际变化的字段并进入素材增量日志。任务取消时保留已经安全应用的部分；再次预览和应用是幂等的，可以继续完成剩余记录。
- `manual` 记录始终跳过。原先由 `filename` 或 `filename_keywords` 生成的字段不作为可信元数据再次喂给分类器，避免自动结果自我证明；规则不再命中时会回到未分类。
- `pending` 素材使用路径哈希集合增量维护。新建、更新、日志重放、人工编辑和删除都会同步更新计数，左侧待确认入口无需每帧遍历完整素材库。
- 整个事务只修改 PsyReaSFX 索引，不重命名、不移动、不复制，也不回写源音频文件。

## UCS 虚拟目录与候选确认

- 左侧 UCS 目录直接使用官方目录的确定性顺序，按 `Category → SubCategory → CatID` 展开；只渲染当前库中计数大于零的节点，中英文界面分别使用对应名称。
- 素材计数由独立聚合缓存维护，每帧最多处理 4,000 条。分类、导入、删除和人工编辑只触发缓存失效；目录展开与折叠本身不会遍历素材库。
- 点击任一级节点后进入对应结果视图，沿用已有分批筛选和分块排序流水线。物理来源、逻辑音效库和磁盘目录保持不变。
- 保存搜索新增 UCS 三层筛选字段；旧搜索保持兼容，缺少筛选字段却声明 UCS 视图的异常记录会安全退回“全部素材”。
- 待确认素材在元数据侧栏显示最多三个有效候选、分值与命中依据。用户单击后写为 `manual / manual`，因此之后的自动扫描不会覆盖。
- 确认前的完整 UCS 字段保存在最多 64 条的会话内撤销队列；撤销会恢复原来的 `pending` 候选及依据。素材被删除或再次人工编辑时会清理对应撤销记录，避免恢复过期状态。

## UCS 搜索提示

- 从当前搜索串的最后一个词元提取提示片段，兼容普通词以及 `category:`、`subcategory:`、`catid:`、`ucs:` 字段前缀；排除词和其他字段不弹出 UCS 建议。不足两个字符时同样不提示，避免产生大面积无意义结果。
- 提示范围固定为官方 753 条 UCS 目录，最多返回七条，不读取或遍历用户的 50 万条素材索引。
- 排序优先级为 CatID 精确匹配、CatID 前缀、SubCategory 精确/前缀、Category 精确/前缀，最后才是 CatShort、说明和中英文 Synonyms；同分按 CatID 稳定排序。
- 选择提示会把当前最后一个词元替换为 `catid:<CatID>`，保留此前的其他搜索条件，随后沿用现有分批结果重建流程。

## 后续同一 Beta 批次

0.9.0 Beta 1 已交付 UCS 首轮功能闭环；发布后继续进行真实 REAPER 交互验收：目录展开与筛选、候选确认/撤销、搜索提示定位、50 万条缓存重建，以及中英文和高 DPI 布局。所有自动改写现有库的操作仍必须先提供预览并允许用户确认。
