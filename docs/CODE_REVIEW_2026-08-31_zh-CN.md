# PsyReaSFX 全仓库代码审查（2026-08-31）

## 审查范围

- Lua 主程序、0.8 Beta 3/4/5 合并功能及其持久化数据。
- Desktop 数据库、后台任务、Watch Folder、设置与主窗口生命周期。
- 构建、自检、ReaPack/Release 版本入口和后续可维护性。

本次审查不改变用户可见的工作流，优先处理数据安全、竞态和可重复验证。

## 已修复

### P0：Desktop 数据库打开失败后可能回写空工作区

`StateStore.LoadAsync` 为了让窗口仍能显示，会在数据库异常时返回空状态。旧逻辑随后仍把窗口标记为已初始化，退出时可能用空的音效库、收藏和集合覆盖数据库。

现在数据库打开失败后会进入禁止写入状态，主窗口不会启动 Watch Folder、自动补封面或退出保存。所有写接口也会统一拒绝写入，避免一次启动故障扩大成数据丢失。

### P1：Lua 核心 TSV/配置文件直接覆盖写入

配置、音效库、索引、集合、搜索、历史、Region、响度、失败任务、工程使用记录等原先直接以 `wb` 打开最终文件。异常退出可能留下空文件或半文件。

现在统一采用临时文件、完整关闭、旧文件回滚、原子替换的写入流程；启动时会恢复替换过程中留下的上一代文件，并丢弃不可信的半成品临时文件。

### P1：来源重定位存在引用合并遗漏

- “最近使用”路径被改写后没有标记配置变更，重启会回到旧路径。
- 集合中目标路径已存在时，顺序数组可能出现重复项，计数也可能错误。
- 工程使用记录中新旧路径同时存在时，旧逻辑会覆盖已有记录并丢失次数。

现在会去重顺序、修正集合计数、合并工程使用次数并保留较新的动作时间，同时正确标记待保存状态。

### P1：重复素材检查可能复用过期文件大小和指纹

音频文件在 PsyReaSFX 外部被替换后，索引中的旧大小可能让重复检查漏掉候选，或者错误复用旧指纹。

现在每次显式重复检查都会读取实时文件大小并重新采样；大小变化会使旧指纹失效并更新索引。指纹同时保存算法版本、大小和修改时间，算法升级会自动清除旧格式。安装 js_ReaScriptAPI 时会在采样前后核对文件状态；未安装时采取保守策略，不跨会话复用持久化指纹。扫描过程中消失或读取期间发生可检测变化的文件不会继续参与分组。候选还可由用户触发分帧逐字节完整确认，确认结果与读取失败单独展示。

### P1：维护任务可能与扫描/导入同时修改资产集合

缺失检查、重复检查、来源重定位之前没有统一隔离扫描、导入和预缓存任务，资产列表改变时可能出现不完整结果或索引引用错位。

现在这些维护任务互斥；来源重定位也必须等待后台目录任务完成。

### P1：Desktop 后台保存枚举实时 UI 集合

部分封面保存和扫描保存通过 `Task.Run` 在后台直接遍历可变状态。用户快速选择、移除库或关闭窗口时，可能得到不一致快照或集合修改异常。

现在先在 UI 线程生成不可变数据库快照，再异步写入 SQLite。常用的库管理、收藏和组织保存也改为异步，减少界面停顿。

### P2：Desktop 设置文件非原子写入

设置保存现在使用写入临时文件、强制刷新和替换最终文件。无法读取的旧设置会先另存为带时间戳的 `corrupt` 副本，再使用默认设置。

### P2：Watch Folder 事件溢出会静默漏更新

扩大了 `FileSystemWatcher` 缓冲区，并监听错误事件。事件队列溢出或目录不可用时会记录日志并安排一次完整的增量扫描，而不是静默停止同步。

### P2：Desktop 数据库缺少向前版本保护

现在会验证 `schema_info`。旧程序遇到未来版本数据库时会停止写入，不会把新结构当成旧结构继续保存。将来提高数据库版本时必须在此处增加事务式迁移。

### P1：SQLite 原生依赖命中 High 级安全公告

依赖审计发现 `Microsoft.Data.Sqlite 8.0.21` 间接带入的 `SQLitePCLRaw.lib.e_sqlite3 2.1.6` 命中 `GHSA-2m69-gcr7-jv3q`。已在 .NET 8 服务线内升级至 `Microsoft.Data.Sqlite 8.0.30`；重新执行 NuGet 漏洞检查后不再存在已知漏洞包。

### P2：缺少代码主线自动验证

新增 GitHub Actions：每个 PR 和 `main` 推送都会解析 Lua 5.3、构建 Desktop Release，并运行 Desktop 完整自检。

## 尚未一次性改动的长期隐患

### P1：Lua 主程序是 27,000 多行、约 480 个函数的共享全局状态单文件

这是目前最大的维护成本。UI、扫描、Transfer、持久化和后台任务互相直接读取 `state`，任何功能都可能意外影响另一个流程。

不建议在一次功能版本中直接拆散。应先引入 `Storage`、`Catalog`、`Jobs`、`Preview`、`Transfer`、`UI` 命名空间和清晰入口，再逐块迁移；ReaPack 仍可发布单文件打包产物。

### 已处理：Lua 数据格式缺少独立 schema 与逐级迁移路径

核心 TSV 已有独立类型和版本头；启动预检会拒绝类型错误、非法版本和未来格式。
迁移前先创建完整数据快照，迁移结果写入日志。集中式注册表显式列出每一个
相邻版本步骤，例如 database `0→1→2→3`；缺少任一步就进入只读保护，不能
跨版本跳写。Lua 自检覆盖旧版可读、当前版写出和未来版拒写。

### P1：Lua 索引保存仍是全量 O(N) 重写

原子写入解决了损坏风险，但大型素材库每次保存仍要排序并重写整个数据库。库规模继续增长后会成为退出和阶段性保存的主要卡顿来源。

建议先拆出 append-only 变更日志，空闲时压缩为完整快照；或者在具备可靠依赖方案后使用 SQLite。

### 已处理：重复检查候选与完整确认混淆

第一阶段继续使用文件大小和首/中/尾采样指纹控制大型库开销，并明确标为“重复候选”。用户要求确认时，第二阶段会分帧比较完整文件内容，分别展示“已确认相同”和读取失败。0.8 仍不提供自动删除；未来若增加清理，也只能基于完整确认并要求用户明确授权。

### P2：路径身份仍基于规范化字符串

大小写和斜杠已统一，但 Windows Junction、符号链接、映射盘与 UNC 指向同一实体时仍可能被认为是不同来源。反过来，盘符重新分配也会改变身份。

建议建立独立 `source_id`，并保存卷标/卷序列号和相对路径作为可选恢复线索，不再让绝对路径承担永久身份。

### P2：Desktop `MainWindow.xaml.cs` 仍有 2,600 多行

播放、筛选、集合、封面、Bridge、持久化和窗口事件耦合在一起。虽然本轮消除了后台快照竞态，但继续增加功能会提高回归概率。

建议拆成 `CatalogViewModel`、`PreviewController`、`OrganizationService`、`ArtworkService` 和 `WindowStateController`，并让窗口只负责绑定与路由。

### P2：REAPER/SWS/ReaImGui 真实集成缺少自动测试宿主

Lua 目前只能做语法检查，无法在 CI 中覆盖 SWS 试听、拖放、声道路由和 ImGui 交互。Desktop 自检也不能证明所有真实声卡和 REAPER Bridge 环境。

建议建立可注入的 REAPER API 适配层，并准备一套小型测试音频库与人工验收脚本。

### P3：发布入口命名仍存在历史包袱

主 Lua 文件仍名为 `PsyReaSFX_v0_7_23_Stable.lua`，但内部和 ReaPack 已进入 0.8 Beta。继续沿用容易让构建脚本、人工打包和问题报告混淆。

在 0.8 Stable 前应确定稳定入口名，并由发布脚本生成带版本的 ZIP，避免手工复制版本号。

## 建议实施顺序

1. 保持本轮安全修复，完成真实 REAPER 大库回归。
2. 建立 Lua 数据 schema/迁移注册表和存储接口。
3. 把 Lua 后台任务统一成单一调度器，明确互斥与取消规则。
4. 拆分 Lua/ Desktop 巨型文件，但保持 UI 和数据格式不变。
5. 增加大库性能基准、路径迁移测试和真实 REAPER 验收矩阵。
6. 最后再继续 0.8 Stable 之后的新功能，避免在旧耦合结构上继续堆叠。
