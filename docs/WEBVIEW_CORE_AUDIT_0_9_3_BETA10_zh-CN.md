# WebView Beta 10 底层复查与验证边界

## Beta 11 修正与追加验证（2026-11-10）

- **纠正 Beta 10 的任务栏验证结论**：用户反馈最小化后仍找不到窗口。继续对照原生代码发现 ReaWebAPI 使用 `WS_OVERLAPPEDWINDOW`，此时 `GetParent` 不会返回所有者，旧实现因此提前退出。原模拟测试错误地把它当成所有者查询，未能发现这个问题。Beta 11 改用 `JS_Window_GetRelated(hwnd, "OWNER")`（`GW_OWNER`），保留名称、窗口类和 REAPER 所有者检查，再设置 `WS_EX_APPWINDOW`。不分离所有者、不修改用户工程。
- 新增 `Test-WebViewWindowContract.ps1`：创建并销毁测试进程自己的隐藏窗口，真实验证 `GetParent == NULL`、`GW_OWNER`、APPWINDOW 和保留所有权；修正 Lua 模拟语义，继续覆盖最小化、停靠和错误窗口。该测试不启动 REAPER；实际任务栏分组和点击恢复仍需按验收清单实机确认。依据：[Microsoft GetParent 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getparent)。
- 修正 Windows 缩放/分栏拖动留下小数尺寸、导致 HTML 整数输入阻止整份设置保存的问题：加载、拖动后统一取整并限幅；回归从 `245.6000213` 等旧值开始保存。主题预设颜色与自定义颜色共享同一优先级，旧默认色只迁移一次，避免覆盖用户后续配色。
- 路径选择统一复用原生文件/目录对话框，取消保持原值，不再弹出手填路径框；目录选择失败明确报告。封面异步选择还校验素材与选择代次，避免切换素材后误写。原生对话框请求允许足够的用户操作时间。
- 后台任务在走带栏内显示，详情使用有界文本/路径；重复点击关闭、悬停打开并移入详情、取消任务、窄窗口不重叠均进入浏览器回归。七套主题、关于页链接和路径取消也覆盖交互测试。

日期：2026-11-10。对照仓库中的 [2026-08-31 全项目审查](CODE_REVIEW_2026-08-31_zh-CN.md)、[Lua 优化审查及 11 月 9 日修复记录](LUA_OPTIMIZATION_REVIEW_0_9_zh-CN.md)，继续检查共享 Lua 服务与 WebView 调用边界。不是仅按旧报告的“已修复”标记判断，也不以界面按钮存在代表功能通过。

## 本轮确认并修复

| 问题 | 修改与证据 |
| --- | --- |
| B5 同类风险仍存在：历史、已试听集合、工程使用记录跨帧用 `next()` 遍历正在变化的表 | 统一固定键序列；删除条目跳过，新增条目由下一轮 dirty 保存；集合顺序也复制后遍历。回归在第一帧后插入 2,000 条、删除待处理条目及移动集合顺序，验证原有有效行无遗漏、无重复。 |
| F11：大量收藏随配置同步写入 | 不改变 TSV schema。自动保存捕获小配置并分帧写收藏，保留原子提交；保存期间的新修改保持 dirty，失败重试。手动保存/退出接管并取消未完成自动保存；移除来源、重置等事务先终止临时写入。25,000 条收藏覆盖多帧、同时编辑、写入/提交失败和同步接管。 |
| AI 密钥保护前会产生明文临时文件，且同步等待 PowerShell | 当前用户专用命名管道传送内存中的密钥，随后由 Windows DPAPI 加密；请求 JSON、命令行和磁盘不含密钥。保存异步完成后才确认成功；超时/取消清理任务，预设身份在保存期间固定。旧明文残留仍在启动时清理。真实 PowerShell 管道/DPAPI 往返、两组密钥隔离、文件泄露检查及 Lua 预设/失败路径通过。Lua 字符串的内存回收不等同安全擦除。 |
| 新异步作业可能被 RPC 直接序列化 | 保存响应等到加密与配置提交完成才发送，仅返回成功或错误；作业内存对象不能进入 JSON 响应。宿主测试使用合成密钥确认等待期间不发送内容。 |
| 数值限幅把 `0` 当成缺省值 | `Number(value) || minimum` 改为显式有限数校验；音量 0 dB、Pitch 0 st 保持零值。音量双击复位与输入回归覆盖；收起 FX 仍可调节，FX 复位不再改变独立音量。 |
| 异步选区可能作用于切换后的素材 | 精确编辑、指针选区与带选区的试听请求携带素材路径，前后端都校验身份；详细波形保留路径/序号检查及有界缓存。 |
| 重定位提交失败后，再次保存旧数据失败却报告“已恢复” | 检查两份回滚写入结果；若仍失败，进入只读保护并指向重定位前备份，防止继续保存混合代次。正常迁移和失败回滚继续使用既有事务流程。 |
| 最小化后重复运行持久脚本触发 REAPER 实例选择 | 公共 `PsyReaSFX.lua` 成为即时退出的启动入口，`PsyReaSFX_Runtime.lua` 持有后台循环。重复运行公共入口调用已有窗口的 Show/Focus，保留任务与试听。测试覆盖首次启动、恢复、过期窗口和缺失运行文件。 |
| Windows 浮动 WebView 无任务栏入口 | 在 js_ReaScriptAPI 可用时，仅对名称、窗口类和 REAPER 所有者均匹配的窗口设置 APPWINDOW；保留最小化状态，停靠时移除。测试覆盖重复检查、最小化、停靠、错误窗口类及其他宿主。实机任务栏外观仍受 Windows 分组设置影响。 |

## 启动测量

对用户现有索引做只读测试：85,179 条，索引约 65.6 MB，增量日志约 49.5 KB。测试禁止修改用户数据，也不探测或解码源音频。

| 路径 | 索引 CPU 耗时 | 工作片段数 | 按 30 ms defer 间隔估算 |
| --- | ---: | ---: | ---: |
| 原空闲 24 ms 预算 | 2.376 s | 87 | 4.956 s |
| 本版空闲 36 ms 预算 | 2.438 s | 61 | 4.238 s |

改善主要来自减少主循环片段之间的等待，估算约 15%；没有把它描述成解析算法变快。播放期间仍使用 12 ms 预算。多个解析器/GC/缓冲试验未得到稳定收益，未保留这些复杂改动。

这些数值不是 PRS 从点击到可操作的总耗时，未计入 WebView 初始化、其他数据加载及真实 defer 调度。一次底层调用或 GC 不能被 Lua 的片段预算强行打断；本次最大片段约 0.16 s。实际会话记录总耗时、工作耗时、阶段、片段数和最大片段，收录在“复制诊断信息”中。品牌状态先显示、就绪即退出，不设最低展示时间。

复现：运行 `tools/lua_startup_capacity_selftest.lua`，依次传入核心、目录、运行时、日志模块，以及索引、日志路径；最后参数分别为 `0.024` / `0.036`。不给真实路径时使用合成数据。

## 原审查项目与保留边界

- 原子写入/备份恢复、日志兼容、选择与源生命周期、后台任务互斥、目录缓存、搜索/排序、AI 端点隔离等继续运行既有故障与容量回归。共享模块作用域检查、Lua 编译、浏览器 DOM/RPC 检查及源码功能清单进入 CI。
- 旧报告的 T6 后半仍是**重定位确认后的同步事务提交**，包括数据库保存；本次修复其失败保护，未将整个多文件事务拆成可交错修改的后台阶段。超大型来源重定位仍可能短暂阻塞。这是已知性能边界，不能声称消除所有卡顿。
- T12 的搜索文本按需构建继续保留，避免给 50 万条素材长期复制一份搜索字符串。旧 ImGui 专有的列缓存/悬停绘制优化不直接套入 WebView；网页使用虚拟列表和有界数据请求。
- 本轮没有再启动 REAPER 或触发插件扫描。浏览器模拟与 Lua/PowerShell 回归不能替代真实听音、音频设备、跨窗口拖放、多显示器 DPI、任务栏和长时间工程操作。用户已确认 Beta 9 空格路由正常；Beta 10 的续播与窗口行为按[验收清单](WEBVIEW_ACCEPTANCE_0_9_3_zh-CN.md)继续实机验证。
- js_ReaScriptAPI 缺失时保留启动入口唤回功能，不强制安装新依赖。Windows 可能把 PRS 窗口合并到 REAPER 图标组，不保证独立应用身份。

窗口实现参考 [js_ReaScriptAPI 源码](https://github.com/juliansader/js_ReaScriptAPI/blob/master/js_ReaScriptAPI.cpp)、[Windows 扩展窗口样式](https://learn.microsoft.com/en-us/windows/win32/winmsg/extended-window-styles) 和 [Windows 任务栏规则](https://learn.microsoft.com/en-us/windows/win32/shell/taskbar)。

本报告列出已复核的风险和测试边界，不是“再无潜在缺陷”的保证。自动测试最终结果、安装包校验和合并记录随本版发布说明提供。
