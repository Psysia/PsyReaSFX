# PsyReaSFX Desktop 50 万条素材库容量标准

记录日期：2026-09-02
适用分支：`hardening/0.8`

## 标准定义

“支持 50 万条”表示 Desktop 可以在一次性、隔离的目录中完成以下完整链路：

1. 生成 500,000 条确定性素材元数据；
2. 首次写入 SQLite 目录；
3. 从 SQLite 完整读取并转换为正式界面状态对象；
4. 对 500,000 条状态对象执行与主界面同级别的内存字段搜索；
5. 执行 SQLite 完整性检查；
6. 数量、写入审计、搜索结果、数据库体积和内存均满足门槛。

该测试不创建 500,000 个真实 WAV，也不解码波形或封面。真实磁盘扫描、波形、
试听和列表交互使用 50,000 条真实文件夹具另行验收，避免把文件系统极限误当成
目录本身的容量。

## 50 万条硬门槛

| 项目 | 上限/要求 |
|---|---:|
| 加载数量 | 必须精确等于 500,000 |
| SQLite 完整性 | 必须为 `ok` |
| 首次保存 | ≤ 300 秒 |
| 完整状态加载 | ≤ 30 秒 |
| 单次线性搜索 | ≤ 1,000 ms |
| 完整性检查 | ≤ 120 秒 |
| SQLite 主文件 | ≤ 1 GiB |
| 加载后托管内存增量 | ≤ 1.5 GiB |
| 进程峰值工作集 | ≤ 2.5 GiB |

时间门槛故意保留跨机器余量；数量、完整性和空间门槛没有容错。任意一项失败，
容量报告的 `passed` 都会变为 `false`，进程返回非零退出码。

## 分级执行

- 每个 PR：原有 1,000 条真实文件基准，加 25,000 条合成容量冒烟检查；
- RC 候选：运行 50,000 条真实文件交互验收；
- RC/Stable：在参考机运行完整 500,000 条容量门槛并保存 JSON 报告；
- 报告只保存在测试产物中，不进入安装包，也不包含用户素材路径。

本地执行方式：

```powershell
PsyReaSFX.Desktop.exe --hardening-capacity-benchmark 500000 capacity-500k.json
```

## 已落实的实现保障

- 生成器与命令行均拒绝超过 500,000 条，防止误操作无限扩张；
- SQLite 素材写入复用单个预编译参数命令，避免 50 万次重复构造命令和参数；
- 容量基准绕过本机 Lua 自动导入，只读取测试目录，确保数量可重复且不受用户环境污染；
- 基准在保存后释放生成快照，再加载正式状态对象，分别记录两阶段内存；
- CI 的 25,000 条测试执行同一条代码路径，防止容量入口长期失修。

## Lua 端边界

Lua 端没有 20 万、25 万或其他素材数量截断，结果列表绘制也只生成可见行；但
当前搜索结果重建和 TSV 索引保存仍包含同步全量遍历/排序。它们在真实 REAPER
中尚未完成 500,000 条计时，因此本文件不能被解释为 Lua 端已经通过 50 万交互
认证。Lua 端下一阶段必须先将结果重建和保存改为分帧/增量流程，再使用真实
REAPER 环境完成同规模验收。
