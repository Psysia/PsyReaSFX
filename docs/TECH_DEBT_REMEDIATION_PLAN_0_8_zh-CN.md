# PsyReaSFX 0.8 长期隐患处理方案

## 总原则

- [x] 进入 0.8 稳定化封锁期，完成本清单前不新增用户功能。
- [x] 所有工作集中在一个 `hardening/0.8` 分支，不按内部阶段拆成多个公开 Beta。
- [ ] 每一阶段独立提交、独立测试，方便回退和开发审计。
- [ ] 只在全部阻断项通过后发布 `0.8 RC1`；确有回归时最多增加一个 RC2，然后发布 Stable。
- [ ] 不以重写为目标；先建立边界和测试，再逐步迁移现有代码。

## 阶段 0：冻结基线与测试夹具

目标：先固定现在“正确的行为”，避免重构过程中凭感觉判断。

- [x] 保存当前 Lua Stable、0.8 Beta 3 和 Desktop Alpha 8 的完整基线包与 SHA-256。
- [x] 准备可重复生成的脱敏测试数据：空库、5,000 条库、50,000 条库、离线盘、路径迁移库、重复素材库、多声道库。
- [ ] 固定 Lua/EXE 功能对照表和人工验收录像/截图。
- [ ] 记录启动、搜索、滚动、保存、扫描、退出的性能基线。
- [ ] 为收藏、历史、集合、Region、响度、工程使用记录建立往返测试样本。
- [x] 将依赖漏洞检查、Lua 解析、Desktop 构建和自检设为 PR 必须通过。

验收：测试数据可重复创建，当前行为有明确预期，CI 失败时禁止合并。

## 阶段 1：数据格式、迁移与恢复

目标：任何升级、异常退出或旧版本误启动都不能破坏用户数据。

- [x] 给每个核心 Lua TSV 数据文件增加独立 schema 版本头。
- [x] 建立集中式迁移注册表：`旧版本 -> 下一版本`，禁止跨版本跳写。
- [x] 每次迁移前自动创建快照，并记录迁移日志、来源版本和结果。
- [x] 未来格式由旧程序打开时进入只读保护，不允许降级写回。
- [ ] 为原子写入加入故障注入测试：写入中断、替换中断、磁盘满、无权限、文件被占用。
- [ ] 验证 `.bak` 恢复、损坏文件隔离和手动恢复流程。
- [x] Desktop SQLite schema 使用事务式迁移，并验证升级前后的完整性。
- [x] 明确 Lua 与 Desktop 共用/导入数据的唯一所有权，禁止双方同时回写同一份文件。

验收：从 0.7.23 Stable、0.8 Beta 3 升级后数据逐项一致；模拟中断后能够自动恢复；旧程序不能破坏新格式。

## 阶段 2：统一后台任务调度器

目标：扫描、试听、封面、波形、响度和维护任务不再互相抢状态。

- [x] 定义任务类型、优先级、可并行规则和资源锁。
- [x] 重型目录任务只允许一个写任务运行；只读任务必须使用稳定快照。
- [x] 每个任务拥有唯一 generation/token，不再共享可被提前释放的取消源。
- [x] 统一任务状态：等待、运行、取消中、完成、失败、可恢复。
- [x] 统一清理入口，确保取消后文件句柄、预览源、临时文件和 UI 状态全部释放。
- [x] Watch Folder 只合并事件并提交增量扫描请求，不直接修改资产集合。
- [x] 应用关闭时先停止接收任务，再有序取消和等待写任务结束。
- [x] 增加快速切换素材、连续开关侧栏、反复扫描/取消、连续试听的压力测试。

验收：压力测试不闪退、不出现 disposed/collection modified 错误；任务取消后可以立即启动下一任务；退出不留下半成品。

## 阶段 3：路径身份与来源重定位

目标：路径变化不再等于素材身份丢失。

- [ ] 用永久 `source_id` 和 `asset_id` 表示身份，绝对路径只作为当前位置。
- [ ] 保存可选卷标、卷序列号、相对路径和最后成功访问时间。
- [ ] 统一路径规范化服务，覆盖盘符大小写、尾斜杠、UNC、映射盘、Junction 和符号链接。
- [ ] 重定位先生成预览计划，列出迁移、冲突、缺失和外部封面，不直接写入。
- [ ] 冲突时合并收藏、历史、集合、Region、响度和工程使用次数，不允许静默覆盖。
- [ ] 重定位提交必须是事务式；失败时恢复旧来源和全部引用。
- [ ] 增加盘符变化、根目录移动、部分文件缺失、两个根指向同一实体的测试。

验收：来源移动后所有引用完整；同一实体不会重复建库；冲突全部可见且可回滚。

## 阶段 4：代码边界与模块化

目标：降低 27,000 行 Lua 单文件和 2,600 行 Desktop 主窗口的回归风险。

- [ ] 建立 `Storage`、`Catalog`、`Jobs`、`PathIdentity`、`Preview`、`Transfer`、`UI` 明确接口。
- [ ] 禁止新代码直接任意修改全局 `state`，改为通过模块入口改变状态。
- [ ] Lua 源码迁移到 `src/lua/` 模块；发布时自动合成为单个 ReaPack 脚本。
- [ ] 自动生成发布文件和版本头，停止手工维护 `v0_7_23_Stable.lua` 这种历史文件名。
- [ ] Desktop 拆出 `CatalogViewModel`、`PreviewController`、`OrganizationService`、`ArtworkService`、`WindowStateController`。
- [ ] 将中英文字符串集中到资源表，禁止继续散落硬编码。
- [ ] 每迁移一个模块都运行行为对照和性能基线，不在同一提交加入新功能。

验收：发布产物仍为单 Lua 文件；模块可单独测试；主窗口和 Lua 入口只负责装配、事件路由和绘制。

## 阶段 5：大型素材库性能

目标：素材规模增长时不再靠全量扫描、排序和重写维持状态。

- [ ] 给 Lua 索引增加脏记录集合，只保存发生变化的资产。
- [ ] 采用快照加 append-only 日志，空闲时压缩；异常退出可重放日志。
- [ ] 搜索、筛选、库计数和文件夹树建立可失效缓存，明确失效条件。
- [ ] 所有长操作设置每帧预算，禁止在 UI 帧中完整遍历 50,000 条以上集合。
- [ ] Desktop 保存使用序列化写队列，合并重复的组织/活动保存请求。
- [ ] 控制波形、封面和响度缓存的内存上限、磁盘上限与淘汰策略。
- [ ] 建立 5,000、50,000、200,000 条素材基准，并记录机器配置。
- [ ] 后台任务运行时，常规交互不得出现持续性卡顿或输入排队。

验收：50,000 条库的滚动/选择保持跟手；后台任务不阻塞 UI；退出和阶段保存不再全量重写未变化数据。

## 阶段 6：重复素材的确定性确认

目标：将“重复候选”与“确认相同”严格区分。

- [ ] 第一阶段继续使用大小和采样指纹生成候选。
- [ ] 第二阶段对用户要求确认的候选执行完整 SHA-256 或逐字节比较。
- [ ] UI 明确显示候选、已确认、读取失败三种状态。
- [ ] 指纹记录包含算法版本、文件大小和修改时间；算法升级自动失效旧缓存。
- [ ] 0.8 阶段仍不提供自动删除，只提供定位和人工处理。

验收：不同内容不会被标记为“确认相同”；文件变化会使确认结果失效；任何工具都不会删除源素材。

## 阶段 7：真实环境与发布验证

目标：自动测试和真实 REAPER 验收共同决定能否发布。

- [ ] 建立 REAPER/SWS/ReaImGui API 适配层，允许 Lua 核心逻辑使用 stub 测试。
- [ ] 自动测试覆盖搜索、集合、迁移、任务取消、重定位、Transfer 和数据恢复。
- [ ] 真实环境覆盖至少两个 REAPER 版本、不同 DPI、无 SWS、无 FFmpeg、离线盘和多声道文件。
- [ ] Lua 与 Desktop 分别运行不少于两小时的连续试听和快速切换测试。
- [ ] 完成依赖漏洞、许可证、SHA-256、ReaPack 索引和安装包内容审计。
- [ ] 更新中英文更新日志、用户指南、恢复指南和已知限制。

验收：自动检查全部通过，人工验收无 P0/P1/P2 未解决问题，发布包可从全新环境安装并读取旧数据。

## 0.8 RC1 发布门槛

- [ ] 上述阶段 0-7 全部完成。
- [ ] 未解决问题列表中没有 P0、P1、P2。
- [ ] 真实用户数据迁移前后数量和关键字段一致。
- [ ] Lua/EXE 连续压力测试无闪退、无数据损坏、无后台任务死锁。
- [ ] NuGet 和其他依赖不存在已知 High/Critical 漏洞。
- [ ] GitHub Actions 全绿，Release 更新日志包含每个内部阶段的提交记录。
- [ ] RC1 只接受回归修复，不再接受新功能。

## 执行顺序摘要

1. 冻结基线和测试数据。
2. 数据 schema、迁移、原子恢复。
3. 后台任务调度和取消生命周期。
4. 路径永久身份与事务式重定位。
5. 在测试保护下拆分 Lua/Desktop 巨型文件。
6. 大库增量存储和性能优化。
7. 重复素材完整确认。
8. 真实 REAPER 验收，发布 0.8 RC1。
