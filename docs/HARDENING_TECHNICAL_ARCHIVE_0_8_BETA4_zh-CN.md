# PsyReaSFX 0.8.0 Beta 4 完整稳定化技术档案

记录日期：2026-09-08

实施分支：`hardening/0.8`

稳定化起点：`c76d9cb`（0.8 Beta 3 功能开发完成时的源码基线）

首个硬化提交：`972d2e3`

代码收口提交：`e3ead43`

公开版本：`0.8.0 Beta 4`；线上热修复：`0.8.0 Beta 4.1`、`0.8.0 Beta 4.2`；正式收口：`0.8.1`

## 1. 文档目的

本文不是最后几轮修改的摘要，而是从 2026-08-31 第一次全仓库代码审查开始，完整记录 PsyReaSFX 0.8 稳定化工程的原因、范围、实施顺序、架构变化、数据安全协议、50 万条容量标准、自动测试证据、发布边界和后续真实环境验收项目。

这轮工作的核心目标不是继续增加界面功能，而是先解决长期积累的数据安全、并发、卡顿、路径身份和代码耦合问题，使 Lua 与 Desktop 后续开发建立在可测试、可恢复、可扩展的基础上。

## 2. 起点：为什么暂停新功能

0.7.23 Stable 已经形成完整的浏览、试听、波形、Artwork、集合、搜索、工作流、Transfer 和文件夹级联导航体系。0.8 Beta 1 至 Beta 3 又加入中断恢复、数据快照、静默 Watch Folder、缺失检查、来源重定位、重复候选和 REAPER 工程关联。

但 2026-08-31 的审查确认：继续在旧结构上增加功能，会放大数据损坏、竞态和大库卡顿风险。因此项目进入稳定化封锁期，原则是：

- 暂停新增用户功能；
- 先固定已发布行为与安装包哈希；
- 每个风险独立提交、独立验证，便于定位和回退；
- Lua 发布仍保持单文件，内部源码才进行模块化；
- 自动测试和真实 REAPER 验收共同决定能否进入 RC/Stable。

基线包包括 0.7.23 Stable、0.8 Beta 3 和 Desktop Alpha 8 Light RC1；其 SHA-256 记录在 `HARDENING_BASELINE_0_8_zh-CN.md` 中。

## 3. 初始审查发现的问题

### 3.1 立即风险

| 级别 | 问题 | 可能后果 |
|---|---|---|
| P0 | Desktop 数据库打开失败后仍可能把空工作区当成正常状态保存 | 原目录、收藏和集合被空数据覆盖 |
| P1 | Lua 核心 TSV/配置直接覆盖最终文件 | 异常退出留下空文件或半文件 |
| P1 | 来源重定位没有完整合并所有引用 | 收藏、集合、历史、Region 或工程使用记录丢失/重复 |
| P1 | 重复检查可能复用外部替换前的大小和指纹 | 漏检或错误候选 |
| P1 | 扫描、导入、维护任务可同时修改素材集合 | 索引错位、集合修改异常、随机崩溃 |
| P1 | Desktop 后台线程枚举仍在变化的 UI 集合 | 保存到不一致快照或抛出并发异常 |
| P2 | Desktop 设置直接覆盖 | 设置文件损坏后无法恢复 |
| P2 | Watch Folder 事件队列溢出没有补偿扫描 | 文件变化永久漏入索引 |
| P2 | 数据库没有未来 schema 写保护 | 旧程序破坏新版数据库 |
| P1 | SQLite 间接依赖命中高危公告 | 发布依赖存在已知安全风险 |
| P2 | 主线没有持续集成门禁 | 回归只能依靠人工发现 |

### 3.2 长期结构隐患

- Lua 是约 27,000 行、约 480 个函数的共享全局状态单文件，UI、扫描、存储、试听和 Transfer 相互直接访问状态。
- Lua 大型目录保存长期依赖 O(N) 全量排序与重写。
- 路径字符串同时承担显示位置和永久身份，盘符变化、Junction、映射盘或 UNC 会制造重复身份或丢失身份。
- Desktop 主窗口承担目录、播放、封面、组织、Bridge、设置和窗口生命周期，修改半径过大。
- REAPER/SWS/ReaImGui 没有可注入宿主边界，纯自动测试难以覆盖核心算法。
- 历史发布入口仍沿用 `PsyReaSFX_v0_7_23_Stable.lua` 文件名，版本识别容易混乱。

## 4. 稳定化实施流程

### 阶段 0：安全基线和数据格式

提交起点：`972d2e3`

- 为 Lua 核心数据建立独立类型和 schema 版本头。
- 建立只允许相邻版本逐级升级的迁移注册表；缺少任何一步就停止写入。
- 未来版本数据由旧程序打开时进入只读保护。
- Lua 写入统一改为临时文件、完整关闭、备份旧代、原子替换；启动时识别并恢复中断事务。
- Desktop 数据库打开失败后进入禁止写入状态，不启动 Watch Folder、自动封面或退出保存。
- Desktop 设置改为原子写入；损坏旧文件先保存带时间戳的副本。
- SQLite 升级到安全服务版本，并加入依赖漏洞审计。

### 阶段 1：统一后台任务生命周期

代表提交：`a28309c`

- 任务统一为等待、运行、取消中、完成、已取消和失败状态。
- 每个任务拥有独立 generation/token，旧任务取消不再提前释放仍在收尾的资源。
- 扫描、导入、Transfer、缺失检查、重复检查、缓存检查等目录写任务共享排他资源。
- Watch Folder 只合并事件并提交扫描请求，不直接修改素材集合。
- 关闭程序时先拒绝新任务，再取消、等待、释放原生资源并保存最终快照。
- 压力测试覆盖 250 次连续试听代次和 64 次连续组织保存请求。

### 阶段 2：路径身份和来源重定位

代表提交：`97cd72b`、`bdfdca6`、`53e4c68`、`063fbe6`

- 引入稳定 `source_id` 与 `asset_id`，绝对路径只表示当前位置。
- 保存来源内相对路径、卷线索和最后可访问时间。
- 重定位先分帧生成迁移、冲突、缺失和外部封面计划，确认后才提交。
- 收藏、最近使用、试听状态、集合、Region、响度、失败任务和工程使用记录一并迁移。
- 路径冲突不静默覆盖；离线素材保留身份，不因暂时断盘自动删除。
- 自动测试覆盖根目录移动、部分缺失、身份冲突回滚、NTFS Junction、扩展路径前缀和盘符变化模型。

### 阶段 3：Desktop 服务边界和性能

代表提交：`5e5cee9`、`c749bb3`、`f6e5389`、`4337a03`、`476a3ac`、`35f7d99`、`81a587e`、`9781318`

- 拆出 Storage、Catalog、Jobs、PathIdentity、Preview、Transfer、Artwork、Organization 和 WindowState 边界。
- UI 线程先冻结不可变快照，后台存储不再枚举实时 WPF 集合。
- SQLite 资产保存按稳定身份比较，只插入/更新变化记录、删除已确认移除的记录。
- 写入进入单一后台串行队列；短时间重复请求合并为最新快照。
- 组织保存压力测试 64 次请求实际执行 1 次、合并 63 次，最终数据等于最后请求。
- Artwork 内存缓存限制为 160 项，波形内存缓存限制为 320 项；RWF 磁盘缓存上限 8 GiB，并只淘汰可重建缓存。

### 阶段 4：Lua 模块化但保持单文件发布

代表提交：`2ba7766`、`5970c7e`、`bb600a4`、`e3ead43`

- 维护源码机械拆分到 `src/lua/`，按启动、UI、状态、宿主、任务存储、目录、增量算法、分析和运行时组织。
- `Build-LuaRelease.ps1` 按固定清单合并模块并写入版本头，ReaPack 用户仍只安装一个 Lua 文件。
- CI 将生成结果与仓库兼容镜像逐字比较，阻止忘记重新构建。
- 新增 `AppState` 状态入口和 `Host` 宿主适配器；存储、目录、分析和重复确认模块可在没有 REAPER 的测试环境中执行。
- 架构审计禁止核心模块重新直接调用全局 `reaper`，并锁定旧式全局 `state` 写入数量，技术债只能持平或减少。
- 英文模式增加运行时漏译登记，诊断信息可显示未覆盖文案数量。

### 阶段 5：重复候选与确定性确认

代表提交：`4ba8b09`、`1c59428`、`6b5904f`、`88514a1`

- 第一阶段仅按实时文件大小与首/中/尾采样指纹生成“重复候选”。
- 指纹包含算法版本、大小、修改时间和来源；算法升级或文件变化会自动失效。
- 安装 js_ReaScriptAPI 时核对修改时间；未安装时主动检查仍可运行，但不跨会话盲目复用指纹。
- 第二阶段按用户要求分帧逐字节比较完整文件，明确区分候选、确认相同和读取失败。
- 0.8 不提供自动删除，任何源音频都不会被工具修改或删除。

### 阶段 6：50 万条结果与缓存算法

代表提交：`3036e53`、`449e0e8`、`41c54f2`、`a8e5526`、`3ab5dff`、`bb0f894`、`9e0e7db`

- 结果重建改为分块筛选、小块排序、分帧归并和分帧恢复选择；条件变化直接丢弃旧代次。
- 目录计数、目录缓存、导入恢复检查、重复检查、波形预缓存和来源绑定全部使用条数与时间双预算。
- 旧结果会保留到新结果完整生成，避免中间状态污染界面。
- 测试规模分为：5,000 条日常真实文件基准、50,000 条真实交互验收、500,000 条合成容量门槛。

### 阶段 7：代次绑定的增量日志

代表提交：`e57e719`、`9cbc140`、`5178c02`、`9b2c0c1`、`fad5b9b`

- 完整目录快照拥有单调递增 generation。
- 素材增量日志必须绑定相同代次，每条记录带校验码，文件必须完整结束。
- 解码器先验证整份日志，再统一应用，绝不部分重放。
- 同一素材的重复修改只保留最后状态；累计 10,000 个不同素材后压缩为新快照。
- 标记、工作流、Artwork、元数据和试听次数使用小型增量日志；未知修改路径自动安全回退为完整快照。
- 新快照提交成功后才清理旧日志；异常中断时，错代次日志自动失效。

### 阶段 8：所有随目录增长的工作分帧化

代表提交：`53e4c68` 至 `06387e0`

- 扫描收尾、取消导入、重建来源、封面懒失效、完整快照、导入提交、清空 Artwork 缓存均改为可取消的分帧任务。
- 移除来源或逻辑库先在只读快照和影子引用中准备完整结果，全部成功后一次切换；取消时恢复已处理引用。
- 播放列表、项目素材箱、工程使用、试听历史、本次试听高亮、Region、响度和失败任务都进入后台原子分帧保存。
- 保存期间产生的新事件进入待处理队列，当前提交后合并回脏状态，不丢失并发变更。
- 至此，自动保存、扫描、重建、重定位、重复检查、缓存检查和结果构建均有帧预算；只保留立即备份和退出时的同步耐久性兜底。

### 阶段 9：最终收口

代码收口提交：`e3ead43`

- Region、响度和失败任务 50 万条持久化容量测试全部补齐。
- AppState、Host、i18n、任务模型和架构边界自检全部接入 CI。
- 完成模块发布源、兼容单文件镜像和自动构建一致性校验。
- Desktop 自检改为只读取一次性测试夹具，绝不发现或导入开发者/用户的真实 Lua 数据；有 FFmpeg 时验证真实 FLAC 输出，无 FFmpeg 时验证明确失败和 WAV 安全降级。
- 合并主分支后保留同期新增的独立 ReaScript 工具和仓库主页结构，没有覆盖其他开发成果。

## 5. 当前数据安全保证

1. PsyReaSFX 不修改、移动或自动删除源音频。
2. 核心数据和设置使用临时文件、备份代和原子替换。
3. 成组恢复要么全部提交，要么整体回滚。
4. 未来 schema 由旧版本打开时只读，不降级写回。
5. 迁移前创建数据快照并记录来源版本和结果。
6. 增量日志必须通过代次、字段、逐条校验和完整文件检查。
7. 数据库打开失败时 Desktop 禁止写入，避免空状态覆盖有效数据。
8. Lua 与 Desktop 分别拥有自己的数据存储；Desktop 对 Lua TSV 只做一次性只读导入，不双写同一数据源。
9. 离线来源和暂时缺失素材保留身份，只有明确的用户操作才能移除来源。
10. 重复检查不会把采样候选冒充为已确认相同，也不会自动清理文件。

## 6. 50 万条容量标准和实测证据

“支持 50 万条”指目录、状态、搜索、完整性和内存容量达到明确门槛，不代表已经自动覆盖 50 万个真实 WAV 的解码、封面和声卡试听。

### Desktop 参考机结果

环境：Windows 10.0.19045、16 个逻辑处理器、.NET 8.0.29。

| 项目 | 实测 | 门槛 |
|---|---:|---:|
| 首次 SQLite 保存 | 102.27 秒 | ≤ 300 秒 |
| 完整状态加载 | 2.57 秒 | ≤ 30 秒 |
| 单次线性搜索 | 28.61 ms | ≤ 1,000 ms |
| SQLite 完整性检查 | 13.68 秒 | ≤ 120 秒 |
| 数据库主文件 | 488.90 MiB | ≤ 1 GiB |
| 加载后托管内存增量 | 801.24 MiB | ≤ 1.5 GiB |
| 进程峰值工作集 | 890.20 MiB | ≤ 2.5 GiB |
| 结论 | 通过 | 全项通过 |

### Lua 结果引擎

500,000 条合成目录完成升序、筛选、降序和选中项定位：549 个分帧步骤，总计算 1.33 秒，最长单步 82 ms（包含 Lua GC），测试内存约 195.8 MiB，全部断言通过。

Region、响度和失败任务各 500,000 条分别在 125 个分帧步骤内完成持久化容量测试。CI 日常使用 25,000 条冒烟规模，避免门禁失修；完整 500,000 条测试用于 RC/Stable 候选。

## 7. 自动验证矩阵

每个 PR 和 `main` 推送执行以下检查：

- Lua 5.3 语法解析；
- 模块化源码合并与发布单文件逐字一致；
- Lua 原子持久化故障注入、事务恢复和真实 Windows 文件锁测试；
- 完整文件重复确认、指纹失效和保守降级测试；
- 25,000 条结果重建、目录缓存和增量持久化容量测试；
- 素材日志截断、损坏、错代次、重复重放和 10,000 条压缩门槛测试；
- Host、AppState、i18n 和任务协调器自检；
- Lua 架构边界审计；
- Desktop Release 零警告、零错误构建；
- NuGet 直接与间接依赖漏洞审计；
- Desktop 完整自检；
- 1,000 条一次性真实文件目录基准；
- Desktop 25,000 条合成目录容量冒烟检查。

Desktop 自检还覆盖数据库迁移、未来版本拒写、Lua schema 3 导入、组织数据往返、Region、试听声道、Transfer、备份恢复、缓存路径、路径迁移冲突回滚和关键 UI 交互。

## 8. 为什么发布为 Beta 4

0.8 Beta 3 已于 2026-08-31 前发布，包含缺失检查、来源重定位、重复候选和工程关联的第一版功能。随后 49 个提交没有继续扩张用户功能，而是对 Beta 3 功能集及整个底层进行系统硬化。

因此本次使用新的 `0.8.0 Beta 4` 标签，不移动或覆盖 Beta 3 标签。这样 Git 历史、Release 资产、ReaPack 版本和用户问题报告都能准确对应实际代码。

发布策略：

- `0.7.23` 继续作为长期可下载 Stable；
- `0.8.1` 与 `0.7.23` Stable 及全部 `0.8.0` Beta 审计版本在同一个 ReaPack 包中共存；
- Stable 用户不会被自动切换到 Beta；
- 用户启用该包的 pre-release 后，可在 Versions 菜单主动选择 Beta 4.2；
- GitHub Beta 4 系列 Release 只提供对应 Lua 测试包，不混入新的 Desktop 构建。

## 9. 升级、在线测试与回退

### ReaPack 测试

1. 同步 Psysia ReaPack 仓库。
2. 右键 PsyReaSFX，启用 `Enable pre-releases (bleeding-edge)`。
3. 从 `Versions` 选择 `0.8.0-beta4`。
4. 首次启动先确认原有库、收藏、集合和历史数量，再执行扫描或重定位。

### 手动测试

下载 GitHub Release 的 Beta 4 ZIP，保留原数据目录备份后覆盖脚本与随包资源。Release 页面公开的 SHA-256 可用于确认下载没有损坏。

### 回退

ReaPack 用户可在同一包的 `Versions` 中重新选择 `0.7.23`。如果 Beta 4 已升级数据 schema，0.7.23 应按未来格式保护策略停止写入；需要完全回退数据时，应同时恢复升级前自动生成的数据快照，不能只替换脚本后继续写新版数据。

## 10. 仍需线上和真实环境验证

以下项目是 Beta 4 的验收范围，不表示已经确认存在代码缺陷：

- 至少两个 REAPER 版本和不同 DPI/缩放比例；
- 安装与未安装 SWS、安装与未安装 FFmpeg 的组合；
- 本地盘、断开后重新连接的盘、映射盘和 UNC；
- 单声道、立体声与多声道素材；
- 0.7.23 真实用户数据升级前后库、素材、收藏、集合、历史和 Region 数量对照；
- 50,000 个真实文件的首次扫描、滚动、搜索、连续选择、试听、退出和恢复计时；
- 连续两小时快速切换试听与后台任务压力；
- 扫描中断、文件占用、无写权限和磁盘空间不足；
- 来源重定位的完整成功、部分缺失、目标冲突和取消；
- 异常关闭后快照、检查点与增量日志恢复。

## 14. 首次线上测试事件：Beta 4.1 排序热修复

Beta 4 发布后的首次真实 REAPER 启动在合并单文件第 7532 行触发 `invalid order function for sorting`。问题来自主结果列表升序比较器使用 `condition and ascending or descending` 模拟三元表达式：当升序比较返回 false 时，Lua 会继续求值降序分支，导致两个不同元素可能互相都被判定为“小于”对方，破坏 `table.sort` 要求的严格弱序关系。

此前 25,000/500,000 条结果引擎容量测试使用独立、正确的测试比较器，只验证了分块排序与归并算法，没有复用主窗口生产比较器，因此没有暴露该错误。

Beta 4.1 的处理：

- 把升序和降序改为显式互斥分支；
- 相等值始终返回 false；
- 主结果的字段比较与路径兜底比较统一复用同一个严格比较函数；
- 自动测试新增升序、降序、相等值和重复值断言，并直接触发 `table.sort`；
- 保留 Beta 4 标签作为事故审计边界，ReaPack 和 Release 以 Beta 4.1 作为后续测试入口。

## 15. 第二次线上测试事件：Beta 4.2 扫描整理进度热修复

真实 42,913 文件库在扫描完成、进入“整理索引”阶段后，于合并单文件第 24758 行触发 `attempt to index a boolean value (local 'session')`。进度绘制使用 `session and not session.silent` 计算可见性，却把这个布尔结果继续当成会话对象读取；正常可见会话因此被折叠为 `true`。

异常发生在 `BeginChild` 与无条件 `EndChild` 之间，Lua 提前退出当前绘制函数，使既有的 `EndChild` 没有机会执行，ReaImGui 随后报告 `Missing EndChild()`。后一个窗口是同一异常的栈清理级联结果，并非独立的布局缺陷。

Beta 4.2 的处理：

- 新增可见进度会话守卫：只返回非静默的 table 会话，其余输入统一返回 nil；
- 进度窗口保存并使用真实会话对象，不再复用布尔可见性结果；
- 保留 `EndChild` 的无条件闭合位置，根因消失后正常走完 ReaImGui 栈清理；
- 自动测试覆盖正常、静默、nil 与异常布尔输入；
- 保留 Beta 4.1 标签作为首次线上事故边界，以 Beta 4.2 作为后续大库扫描测试入口。

## 16. 0.8.1 文件夹拖放修复与正式收口

Beta 4.2 线上测试发现，Windows 文件管理器拖入真实文件夹后仍可能显示“请拖入文件夹”。旧实现先依赖宿主文件检测，再使用 `os.rename(path, path)` 判断目录；该无分隔符调用对文件和目录都可能成功，同时在长路径、UNC 路径及不同文件系统上存在不一致返回，因而不适合作为拖放类型判据。

0.8.1 的处理：

- 使用末尾带目录分隔符的探针，使普通文件与目录的系统调用结果明确分离；
- Lua 路径探针失败时，以 REAPER 原生文件/子目录枚举识别非空长路径或 UNC 目录；
- 外部拖放路径统一清理成对引号、尾部 NUL 和多余目录分隔符；
- 自动测试直接覆盖真实目录、Unicode 路径规范化、普通文件、缺失路径和原生枚举兜底；
- 结束 `0.8.0 Beta 4.x` 测试序列，后续发布从正式版本 `0.8.1` 继续递增。
