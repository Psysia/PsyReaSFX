# Beta 15：停靠切回浮动窗口的崩溃排查

用户确认 Beta 14 的停靠卡顿已改善，但解除停靠后 REAPER 卡死并闪退。
本轮读取 Windows 崩溃记录、检查安装版本与源码，并使用隔离窗口回归；没有启动或操作用户的 REAPER。

## 证据与边界

- 2026-11-11 的两条 Windows APPCRASH 记录分别为 `0xc0000005`、`0xc000041d`，均位于 `reaper.exe`（7.8.5.0）偏移 `0x38eb98`。
- 已安装 DLL 的 SHA-256 与 `0.3.9.30-prs.1` 一致，ReaPack 所属包为 `PsyReaSFX WebView Runtime.ext / 0.3.9.30-beta2`。这次不是旧 DLL 未更新或包所有权冲突。
- Windows 只保留了报告，没有保留可用 minidump。对对应可执行文件的静态指令核对显示：故障发生在一个虚拟界面控件向父窗口发送查询之后，读取返回的无效指针；虚表布局与 WDL 的可访问性描述查询一致。没有完整调用栈，不能把某个具体重绘或焦点调用认定为已复现的唯一根因。
- 原运行时的 Docker 子容器钩子在移除 tab 时仍可能吞掉宿主的 `WM_SETREDRAW`；同一容器中其他 WebView 也可继续拦截。Windows 原生位置、尺寸回调同时会调用 WebView2，解除停靠又同步重复恢复焦点。

## 修正范围

`0.3.9.30-prs.2` 保留 Beta 14 对顶层 REAPER 重绘的修复，并增加结构切换保护：

1. 解除停靠和关闭停靠窗口进入同一结构切换范围，临时暂停共享 Docker 的重绘拦截，让宿主完成控件树变更。
2. 重绘关闭／开启消息保持配对，支持嵌套、共享 tab、跨切换范围到达的开启消息及宿主销毁。旧 HWND 被复用时不会操作新窗口的记录。
3. WebView2 布局、位置通知、图标刷新和焦点恢复延后到宿主操作返回后；焦点通知合并，`MoveFocus` 不再直接嵌在原生焦点回调中。
4. 浮动窗口的所有权和任务栏入口逻辑保留；不修改 REAPER 工程、素材库或音频处理。

WebView2 的消息循环和重入限制见 [Microsoft 文档](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/threading-model)。静态故障分析与该时序风险相符，但不等于用户环境中的崩溃已被测试复现。

## 验证与验收

自动测试覆盖：宿主顶层重绘、多 tab、嵌套切换、晚到的重绘开启、宿主销毁；运行时模拟检查解除停靠及关闭入口；真实 WebView2 在测试进程创建的窗口中往返切换，检查页面状态、视口和焦点。

运行库提交 `0269fb82493ce7a9666146675054ba342db86fc4` 的 [Windows CI](https://github.com/Psysia/ReaWebAPI/actions/runs/42948446631) 已通过全部 50 项回归，包括真实 WebView2 的无边框与最大化恢复测试。应用包已通过隔离目录中的安装／回滚、校验和与源码匹配检查；ReaPack 包保留原文件归属。

仍需实机确认：保存工程后，升级运行库并完全退出、重启 REAPER；检查停靠→浮动、重复往返、关闭停靠窗口、最小化恢复，以及已有其他 Docker tab 的情况。自动测试不会把依赖锁中的 `native_acceptance_pending` 改为已验收。

## 安装

在 ReaPack 同步仓库，更新 **PsyReaSFX 0.9.3-beta15** 和同一个 **PsyReaSFX WebView Runtime 0.3.9.30-beta3** 包，再完全退出并重启 REAPER。运行时实际版本应显示 **0.3.9.30-prs.2**。旧 DLL 在进程存活期间不会被卸载，仅重跑脚本不能完成更新。

本次沿用原包 ID 和文件归属，不新增第二个竞争 DLL 所有权的包。离线 ZIP 同时包含 DLL、匹配源码、许可证和 SHA-256 清单。
